# 022 Fidelity Audit Findings

**Schema:** Each finding has id, sourceRef, tsModule, severity, disposition, testRef, notes.

Severity: `HIGH` = exploitable / game-breaking, `MEDIUM` = wrong but bounded, `LOW` = cosmetic.
Disposition: `fixed` | `deferred` | `n/a` (intentional TS-only behavior, documented).

ID prefix: `S-` scanners, `A-` AI targeting, `P-` persistence, `C-` combat ranges.

### Scratch — C-source inventory used for the walk

- **Load on logon:** `GEFUNCS.C:79 warenter` → `GEFUNCS.C:104 findships` → `GEFUNCS.C:129 gepdb(GEGET, ...)` → `GEFUNCS.C:153 tossingegame` (sets `status=GESTAT_USER`).

- **Save on logoff:** `GEMAIN.C:1397 warhupa` — `gepdb(GEUPDATE)` + `geudb(GEUPDATE)` then `status = GESTAT_AVAIL`. Combat-locked players (`cantexit > 0`) are killed instead.
- **Save on `x` exit:** `GEMAIN.C:2862 mnu_fightsub` — gated on `cantexit == 0`.
- **Death:** `GEFUNCS.C:1087 killem` — `gepdb(GEDELETE)` + `geudb(GEUPDATE)`; `noships--`.
- **Cleanup:** `GEMAIN.C:1051 gepdb(GELOOKUPNAME, uid)` loop on session destroy.
- **Midnight:** `GEMAIN.C:1067-1335 gemidnighta` — runs against User rows, planet rows, mail rows; does NOT touch active `warsptr` arrays.
