# Implementation Plan: Navigation Autopilot, Spy, Help, and Clear Screen

**Branch**: `016-navigation-spy` | **Date**: 2026-05-07 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/016-navigation-spy/spec.md`

## Summary

Adds four player commands that round out the core action set before the
endgame features (planet attack, mail, teams):

1. **`nav <x> <y>`** — autopilot. Validates target against `univmax = 15`,
   stores target on `ShipState`, sets `holdcourse = 1` (truthy boolean
   semantics — see research D1), and the existing physics tick recomputes
   `head2b` toward the target each tick. Arrival uses floor-based sector
   match; manual `rot/imp/war` silently disengages. Re-issuing replaces
   the target. In-orbit invocation auto-breaks orbit before engaging.
2. **`spy`** — consumes one `I_SPY` (item slot 13) from cargo and writes
   the issuing player's userid into `PlanetState.spyowner`. Mirrors
   `cmd_spy` in `GECMDS.C:6040` exactly: orbit gate (`where >= 10`),
   reject self-owned planets, wormholes, and neutral zone.
3. **`hel` / `?`** — topic-group help (navigation, combat, trade, planet,
   ship). Static reference data, no DB. Per-command help is out of scope.
4. **`cls`** — frontend-only event-log clear. Still flows through the
   command-dispatch path so tokenisation is consistent, but the result
   carries a `clearLog: true` directive that the UI honours; no backend
   state mutated.

The work is mostly additive: new handlers slot into the existing
`CommandRouterService`; physics tick gets one new branch (autopilot bearing
update); two new fields on the Ship Prisma model (`navTargetX`,
`navTargetY`); no new Prisma migration on Planet (`spyowner` already
exists). Help text lives in code as a typed catalog.

## Technical Context

**Language/Version**: TypeScript (strict mode), Node.js 20+
**Primary Dependencies**: NestJS, Prisma, Socket.io (`@nestjs/platform-socket.io`), React 18, Vite
**Storage**: PostgreSQL 16+ via Prisma; in-memory `Map<shipKey, ShipState>` is the live source of truth, async DB flush per existing pattern
**Testing**: Jest (backend), Vitest (frontend)
**Target Platform**: Linux server (Hetzner CPX32) via Docker Compose; modern desktop browser for client
**Project Type**: Web application (NestJS backend + React/Vite frontend)
**Performance Goals**: Per-tick autopilot bearing recompute is O(1) per ship; physics tick budget unchanged from feature 002 baseline
**Constraints**: Constitution Principle III — physics tick uses raw `setInterval`, not `@Interval`; no Redis; balance constants from `GEMAIN.H` preserved
**Scale/Scope**: Four commands, one tick branch addition, one Prisma migration (two ship columns), one frontend command-result extension for `cls`
